## 一、对标开源项目全景

### 1.1 项目定位矩阵

| 项目 | 定位 | 核心架构 | 生产部署形态 | 与 YYC³ 的关系 |
|---|---|---|---|---|
| **Continue.dev** | IDE AI 助手（VS Code/JetBrains/CLI） | 模块化"hub"架构，50+ 模型，插件底盘 | IDE 扩展 + 自建 hub 服务 | 直接竞品——同为"编辑器+AI" |
| **OpenHands** (ex-OpenDevin) | 自主 AI 软件工程 Agent | **Event Stream 架构** + 沙箱运行时 + 多 Agent 委托 | Docker/K8s 沙箱 + Web 控制台 | 高阶竞品——Agent 自主执行 |
| **Cline** | VS Code AI 编码 Agent | Plan/Act 双模式 + **MCP Marketplace** + 人机审批环 | VS Code 扩展 | MCP 生态对标 |
| **LibreChat** | 自托管多 Provider AI 聊天平台 | MIT 开源，多 Provider + Agent + **MCP 一等支持** | Docker 自托管 + 云端 | 数据主权理念相同 |
| **Open WebUI** | 自托管 AI 聊天界面 | 深度 Ollama 集成 + **最强管理面板** + 内建 RAG | Docker/Podman 自托管 | UI/管理对标 |
| **Bolt.new** | 浏览器内全栈 AI 应用构建 | **WebContainer**（Wasm 微 OS + 浏览器内虚拟 FS） | 纯浏览器（零后端） | 纯前端理念相同 |
| **Langfuse** | LLM 可观测性平台 | 追踪/监控/数据集/实验/评估闭环 | Docker/K8s 自托管 + 云端 | 缺失的观测维度 |

### 1.2 关键洞察

**社区共识方向**（综合 Reddit/HN/GitHub 讨论）：

1. **MCP（Model Context Protocol）已成为工具集成的统一标准**——LibreChat/Cline/OpenHands 全部一等支持，OAuth 2.1 + PKCE 鉴权为最佳实践
2. **Agent 能力是差异化核心**——从"对话助手"到"自主执行 Agent"（Plan/Act 模式 + 沙箱执行 + 人机审批）是社区公认演进方向
3. **RAG 是生产必需**——代码库索引 + 向量检索 + 上下文注入是 AI 编码助手的基础能力
4. **可观测性不可缺席**——Langfuse 被 ClickHouse 收购说明 LLM 观测已成独立品类
5. **WebContainer 代表纯前端的极限**——Bolt.new 证明浏览器内运行 Node.js 全栈是可行的

**P1.1 MCP 工具调用闭环**（对标 Cline）
```
现状：MCP 工具清单注入 systemPrompt，AI 回复 JSON 但不执行
目标：AI 回复 {"tool":"fs_read","args":{...}} → 客户端调 MCPClient.callTool() → 结果回传 → AI 继续
实现：
  1. ChatPage 发送后监听 AI 回复中的 tool_call JSON 模式
  2. 匹配已启用 MCP 服务器 → mcpClient.callTool(name, args)
  3. 结果作为 tool_result 消息追加 history → 再次调 sendToActiveModelStream
  4. 循环直到 AI 输出纯文本（无 tool_call）或达最大循环次数（安全限制=5）
安全：
  - 工具白名单（仅用户启用的 MCP 服务器）
  - 每次调用弹窗确认（人机审批环，对标 Cline）
  - 循环深度限制（防无限调用）
```

**P1.2 代码库语义索引（RAG 基础版）**（对标 Continue/Cursor）
```
现状：无
目标：项目文件可被 AI 对话引用
实现（纯前端）：
  1. 文件树遍历（已有 gitEngine.listFiles）→ 按函数/类 chunk
  2. chunk → embedding（复用 local-inference-engine 的 runEmbedding）
  3. 向量存 IndexedDB（新 schema：vectorStore）
  4. 用户消息 → embedding → 余弦相似度 top-K chunk → 注入 systemPrompt
  5. 对话中 AI 可引用具体文件名/函数名（有据可查）
对标：Continue 的 codebase indexing（纯前端版）
```

**P1.3 请求级全链路追踪**（对标 Langfuse 简化版）
```
现状：aiMetricsStore 有聚合指标（延迟/成功率/成本）
目标：单次请求完整链路可查
实现：
  1. 每次 sendToActiveModelStream 创建 traceId
  2. 记录：prompt（脱敏）→ model → latency → tokens → cost → tool_calls[] → final_output
  3. 存 IndexedDB（保留最近 500 条）
  4. PerformancePanel 增"链路详情"视图（点指标看单次请求全链路）
对标：Langfuse trace 视图（本地版）
```

#### Phase 2：Agent 执行引擎（2-4 周）→ "与 OpenHands 能力对齐"

**P2.1 任务分解 + 工具编排引擎**
```
对标：OpenHands Event Stream 架构
设计：
  EventStream {
    events: Array<
      | { type: 'user_message', content }
      | { type: 'ai_plan', steps: [{ id, description, tool, args }] }
      | { type: 'tool_call', tool, args, result, approved }
      | { type: 'ai_response', content }
      | { type: 'error', message }
    >
  }
  
  执行循环：
    1. 用户任务 → AI 生成计划（Plan 阶段，JSON steps）
    2. 逐步执行：每步 = 工具调用（MCP/git/fs/web search）→ 人机审批 → 执行
    3. 所有步骤完成 → AI 汇总（Act 阶段）
    4. 中间结果实时展示（对标 Cline 的 Plan/Act UI）
```

**P2.2 人机审批环（Human-in-the-Loop）**
```
对标：Cline 的 GUI approval loop
实现：
  - 每个 tool_call 触发前弹窗：显示工具名/参数/预期效果
  - 用户可 approve / reject / edit args
  - reject 时 Agent 调整计划（AI 收到 rejection reason）
  - 全部审批历史记录（审计日志）
```

**P2.3 沙箱执行环境**
```
对标：OpenHands Docker 沙箱 / Bolt.new WebContainer
纯前端方案：
  - 文件操作：已有 LightningFS（IndexedDB）
  - 代码执行：Web Worker + import()（受限 JS）
  - Shell：增强终端解释器（已有基础）
  - 网络：fetch（受 CSP 白名单约束）
后端方案（需 Platform）：
  - Platform 仓加 sandbox 容器（Docker per-session）
  - WebSocket 桥接前端 ↔ 沙箱
推荐：先做纯前端版（安全沙箱=Web Worker），后端沙箱作为 Platform 增值服务
```

## 四、生产落地关键决策点

### 4.1 技术选型对比

| 决策点 | 方案 A（推荐） | 方案 B | 理由 |
|---|---|---|---|
| 向量存储 | IndexedDB（原生） | 浏览器 WASM SQLite | IndexedDB 已有基建，无额外依赖 |
| Embedding | transformers.js 本地（codebert-base） | 远程 API | 数据主权优先，本地已就绪 |
| Agent 通信 | 事件流（内存 + IndexedDB 持久化） | WebSocket | 纯前端不需要 WS；人机审批要求同步等待 |
| 沙箱 | Web Worker + import() | Docker（Platform） | 渐进：先浏览器安全，后端按需 |
| MCP 鉴权 | Bearer token（已有） | OAuth 2.1 full | 当前 Bearer 已够；Phase 3 升级 |
| 状态管理 | zustand（已有 30 个 store） | Redux Toolkit | 不换——迁移成本 > 收益 |

### 4.2 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| RAG 索引大项目 OOM | 中 | 高 | 分批索引 + Web Worker 后台 + 文件大小限制 |
| Agent 循环失控 | 中 | 高 | 最大循环深度 + 人机审批 + 超时熔断 |
| MCP 服务器不可信 | 高 | 高 | 白名单 + 工具描述审计（对标 MCP 安全规范）|
| 多 Provider CORS | 低 | 中 | 已有 CORS 白名单；新 Provider 逐一验证 |
| IndexedDB 容量 | 低 | 中 | 配额监控 + LRU 淘汰 + 导出备份（已有） |
