### 2.2 文件级崩溃（3 个文件，1 个根因，已修复）

`DocumentPreviewCore.docxSanitize` / `skillMarkdown` / `SkillDrawer` 三个测试文件在**收集阶段**崩溃：`PdfDocumentPreview.tsx → react-pdf → pdfjs-dist 5.4.296` 在模块求值期执行 `new DOMMatrix()`（canvas.js 的 `SCALE_MATRIX`），jsdom 不实现 DOMMatrix。

修复：[setup.ts](file:///Users/yanyu/YYC3-GitHub/YYC-Cube/YYC3-Pai/dashboard/src/test/setup.ts) 按既有 polyfill 模式（matchMedia/ResizeObserver/IntersectionObserver）追加守卫式 DOMMatrix stub。

### 2.3 级联根因（本轮最重要发现）：react-i18next mock 的 `t` 身份不稳定

**症状演进**：全量跑失败集合逐轮漂移（run1: 10 文件/17 用例 → run2: 24/36 → run3: 9/16 → round4 起稳定为 AuthGuard 单点）。

**取证过程**：`--no-file-parallelism` 顺序跑 → AuthGuard 通过、MBTISelector 反而失败 → 单跑 MBTISelector 仍红 → 文件内二分（1+3 过 / 2+3 挂）→ 忠实探针（临时复制测试文件插桩，用后即删）→ mock 调用日志显示 **API 被无限重复调用**。

**根因**：[setup.ts](file:///Users/yanyu/YYC3-GitHub/YYC-Cube/YYC3-Pai/dashboard/src/test/setup.ts) 旧 mock 每次 `useTranslation()` 返回**新的 `t` 函数**；凡把 `t` 列入 `useEffect` 依赖的组件（如 MBTISelector `[t, targetAgentId]`）每渲染一轮就重跑 effect → 无限 fetch 循环：
1. 本文件内 loading 帧占绝对多数 → `findByText` 采样不到内容帧（MBTISelector 用例 3 失败）；
2. 循环进程吃满 worker CPU → **饿死同机其它 worker** → AuthGuard 的 5s 异步预算被击穿（并行模式稳定失败、顺序模式通过的真正原因）。

**修复**：mock 的 `t`/`i18n` 提升为稳定引用（与真实 i18next 行为一致）。修复后全量运行时长 30s → 16s，佐证 CPU 饿死论。

### 2.4 资源过订阅收尾

默认 `maxWorkers` = CPU 核数在多核开发机上仍会过订阅；`--maxWorkers=4` 实测全绿，且 CI runner（ubuntu-latest = 4 vCPU）天然一致。已固化到 [vitest.config.ts](file:///Users/yanyu/YYC3-GitHub/YYC-Cube/YYC3-Pai/dashboard/vitest.config.ts)（`maxWorkers: 4`）。

### 2.5 防抖加固

[AuthGuard.test.tsx](file:///Users/yanyu/YYC3-GitHub/YYC-Cube/YYC3-Pai/dashboard/src/components/AuthGuard.test.tsx) 文件级 `configure({ asyncUtilTimeout: 5000 })`（默认 1s 对满载 worker 偏紧；注释说明缘由）。
